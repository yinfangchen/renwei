# 人味（renwei）

中文文本的双向「调味」skill：按场景去 AI 味，或者反过来，把大白话变成正式文体 / 标准 AI 腔。也可以只诊断，告诉你哪里像 AI、值不值得改。

## 为什么再做一个 humanizer

这几个前辈项目各有侧重：

| 项目 | 语言 | 场景支持 | 思路 |
|---|---|---|---|
| [blader/humanizer](https://github.com/blader/humanizer) | 英文 | 无 | 维基百科「Signs of AI writing」的 33 条模式 |
| [op7418/humanizer-zh](https://github.com/op7418/humanizer-zh) | 中文 | 无 | 上者的中文本地化 |
| [MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua) | 中文 | 工程/工作沟通场景 | 场景包 + 事实保护 + 评测 |

写 v0.1 时，上表几个项目都还没有专门处理内容创作场景，而这恰恰是 AI 痕迹最「场景相对」的地方：

- emoji 分点在文档里是 AI 味，在小红书里删光了反而假
- 排比在百科条目里是套路，在口播稿里是修辞
- 「解锁」「拉满」在正式文案里违和，在短视频里是平台通用语

所以 renwei 先判场景，再按这个场景自己的「人味标准」改写，不拿一套规则打天下。每个场景包带一张**极性表**，写明通用规则在这个场景里哪些反转、哪些放宽、哪些收紧。极性表只管松紧，压不过事实铁律和防误伤规则，比如店铺回买家时该有的售后礼貌，哪个场景包都删不掉。

## 支持的场景

- **对话/聊天回复**（微信、QQ、群聊、评论区）：删客服腔，回多长看对方要拿这条消息去做什么，多热络看关系，对方要用的信息不砍；私聊在关系不明时给两个语气候选；店铺、客服回买家时保留售后礼貌
- **正式书面**（邮件、周报、汇报、方案、简历、学术论文、技术文档）：改掉套话和欧化句法，语体不降，邮件改完还是邮件，论文改完还是论文
- **长文案**（公众号、博客、知乎）：删宏大开头和升华结尾；立场要清楚，原文没表态就问作者，不替作者站队
- **短视频口播稿**（抖音、视频号）：按「说出来的文字」改：气口、前三秒钩子、数字念法
- **小红书笔记**（朋友圈、微博短帖也走这个包）：emoji 和碎排版保留，均匀分布打破；种草文严禁编造经历
- 其他文本走通用模式库

通用模式库有 41 条中文 AI 痕迹，分四层：词汇与短语、句式与结构、沟通与语气、欧化句法与阅读负担。最前面一节是判定尺度（防误伤与人味保护）。单条特征不定罪，要看密度、均匀度和叠加；真人也常用的说法、引号里的话、编不出来的细节都不动。

场景判不准时，skill 会先问你。在 Claude Code 里，它用 AskUserQuestion 组件列出这段文本最可能的四个场景，各附一句会怎么改；都不对就选「其他」，自己填。

## 诊断模式

问「这段哪里像 AI」「要不要改」，skill 只诊断，不改写。它列出命中的模式和原句，按密度、均匀度、叠加下结论。读着不像 AI 就直说，最多给两处可选改动。

正常改写也先走这一步，改多少跟着诊断走。痕迹扎堆才全面改，零星几处就点改，没有聚集就不改。你说「轻改」或「大改」，以你为准。要是你说导师、老板或朋友已经嫌它像 AI，skill 会把这当证据，辨识度最高的那几处（「值得注意的是」、套话式道歉、破折号）哪怕只出现一次也点改，但不重写。

## 反向模式

- **正式化 / 官腔化**（实用）：大白话 → 工作群通知、正式邮件、书面汇报。skill 不许把承诺改模糊，「今晚发」不能变成「近期发送」，评测用例专门测这一条。
- **AI 腔化**（演示 / 整活）：把模式库反着用，制造教科书级 AI 味，拿来做对比教学正合适。

走不走反向，看输入和目标的语体差，不看发到哪。大白话要写成通知，是反向；「太像 AI 了，要发工作群」「改成人话但要正式」还是正向，语体不动，只去 AI 味。

## 事实铁律

两个方向共用一条底线：

- 数字、日期、价格原样保留，修饰关系也不动；人名、引语不改字。
- 代码标识符、命令、URL、单位和文档选定的英文术语逐字保留。
- 承诺、条件不漂移；「预计」「约」「初步」「可能」这类确定性程度不加强也不减弱。
- 原文没有的事实不补，立场、推荐、排序、因果也不替作者补。
- 唯一例外：口播稿允许数字念法口语化（不损关键精度）。

缺信息时，skill 先交付一个不依赖它的版本，再列出最多三条请你补的事（立场、出处、真实经历、要砍的内容）。

规则冲突时的顺序是：事实铁律 > 判定尺度（防误伤） > 场景包。

renwei 写给人类读者看，不针对 AIGC 检测器，也不承诺检测分数。

## 安装

### Claude Code

```bash
git clone https://github.com/yinfangchen/renwei.git ~/renwei && ln -s ~/renwei ~/.claude/skills/renwei
```

或者直接把整个目录拷进 `~/.claude/skills/`。新会话里说「帮我去去 AI 味」，或直接 `/renwei`。

### 其他 agent

SKILL.md 是纯 Markdown，没有依赖。把仓库路径给任何能读文件的 agent，让它先读 SKILL.md 再干活即可。

## 项目结构

```
renwei/
├── SKILL.md                 # 主文件：流程、诊断、场景判定、事实铁律、审核
├── references/
│   ├── patterns.md          # 通用模式库：目录、判定尺度（防误伤与人味保护）、41 条中文 AI 痕迹
│   ├── scene-chat.md        # 场景包：对话/聊天回复
│   ├── scene-formal.md      # 场景包：正式书面
│   ├── scene-longform.md    # 场景包：长文案
│   ├── scene-video.md       # 场景包：短视频口播稿
│   ├── scene-xhs.md         # 场景包：小红书笔记（含朋友圈、微博短帖）
│   └── reverse.md           # 反向模式：正式化/官腔化 + AI 腔化
└── evals/                   # 测试用例
```
